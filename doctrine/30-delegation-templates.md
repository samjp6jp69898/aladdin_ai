# 派工 Prompt 模板（30-delegation-templates）

> 用法：複製對應模板 → 填掉所有 `{…}` 槽位 → 派工。**槽位填不出來 = 你還沒想清楚，先想清楚再派。**
> 通則見 `10-model-dispatch.md`（三件套、回報合約、模型分級）。派給**已註冊 agent** 時不用這裡的模板——用該 agent 在 pipeline 指令檔裡的專屬模板。
> 所有模板共同鐵則：長產物落檔傳路徑；回報尾行照格式；查程式碼結構走 CLAUDE.md 的 Source-First skill 表；找不到/做不到就回 BLOCKED，禁止編造。

## T1 搜尋（找位置、找用法、找全部出現點）

適用：跨多檔定位、「所有用到 X 的地方」、不確定關鍵字拼法。model：**sonnet**（subagent_type: Explore 或 general-purpose）。

```
目標：找出 {要找什麼}，因為 {接下來要拿結果做什麼——這決定你回報的詳略}。
範圍：{目錄/repo 清單}；已知線索：{關鍵字、可能的別名、相關 skill 腳本}。
要求：
- 結構性資訊（method/enum/欄位/呼叫鏈）優先用腳本查：{貼上 CLAUDE.md Source-First 表中適用的那一行}
- 對每個命中點給 file:line + 一句「它在做什麼」
- 也要回報「確定沒有的範圍」（搜過哪些地方沒有）
驗收條件：{怎樣算找齊——例如「與 grep -rc 的粗計數量級一致」「涵蓋 4 個 repo」「至少驗證 2 個命中點真的讀過」}
回報格式（最後幾行）：
FOUND: <數量>
LIST: <file:line — 一句描述，每個一行；超過 15 個就寫入 {落檔路徑} 只回前 5 + 路徑>
NOT_SEARCHED: <沒覆蓋的範圍，沒有就 none>
```

常見錯誤：不給「動機」→ agent 回一堆無關命中；不要求 NOT_SEARCHED → 假陰性沒人知道。

## T2 實作（已有明確方案，執行修改）

適用：方案已定（誰、改哪、改成怎樣），純執行。model：**sonnet**；機械批次替換可 **haiku**。

```
目標：{改什麼} 以達成 {行為變化}，因為 {動機}。
方案（照做，不要重新設計）：{逐條——檔案、位置、改法；或指向方案文件路徑}
邊界：只動 {允許清單}；禁動 {禁止清單，至少含 localizations/*.json}；跟隨周邊既有風格。
驗收條件（逐條驗，附證據）：
- {測試指令} 綠（貼最後 10 行）
- {lint 指令，必要時帶 NODE_OPTIONS=--max-old-space-size=8192} 乾淨
- {行為級驗證，如：某函式對輸入 X 回 Y}
回報格式（最後三行）：
RESULT: <DONE|BLOCKED>
CHANGED: <file:line 清單或 diff 落檔路徑>
EVIDENCE: <驗收證據的落檔路徑>
```

常見錯誤：方案槽位寫「你看著辦」→ 那是設計不是實作，先派 T4 研究或自己定案。

## T3 重構（行為不變，形變）

適用：整理結構、消重複、搬位置。model：**sonnet**。

```
目標：重構 {範圍}：{要消除的壞味道} → {目標形狀}，因為 {動機}。
不變式（重構的定義，違反即失敗）：
- 對外行為完全不變：{既有測試清單/指令} 重構前後都要綠
- 不順手加功能、不改公開介面{如允許改介面，明列哪些}
步驟要求：先跑一次既有測試確認基線綠，再動手；每個獨立步驟後重跑。
驗收：基線測試綠（前後兩次輸出都貼尾 5 行）+ {結構驗證，如：重複區塊剩 0 處（grep 證明）}
回報格式：
RESULT: <DONE|BLOCKED>
INVARIANT_PROOF: <前/後測試輸出落檔路徑>
CHANGED: <file 清單>
```

常見錯誤：沒先跑基線 → 測試本來就紅，重構完賴給重構。

## T4 研究（弄懂再回來：技術選型、原因調查、文件考古）

適用：需要讀很多東西才能回答一個問題。model：**sonnet**；牽涉裁定/取捨 → **opus**。

```
問題（一句話，可回答的形式）：{…}
動機：答案將用來決定 {…}——所以請對這個決策給出明確建議，不要只羅列。
素材範圍：{檔案/目錄/官方文件 URL/skill 腳本}；優先序：{source > 實測 > 文件 > 筆記}。
要求：
- 每個關鍵結論附出處（file:line 或 URL）與確定度（已驗證/推測）
- 有互相矛盾的來源時，明列矛盾點，別悄悄選邊
- 查不到就寫查不到
驗收條件：{怎樣算答完——例如「問題的 3 個子面向各有結論與出處」「RECOMMENDATION 可直接執行不需再問」}
產出：完整研究筆記寫入 {落檔路徑}；回報只給結論。
回報格式：
ANSWER: <直接回答問題，≤3 行>
RECOMMENDATION: <建議 + 一句理由>
CONFIDENCE: <高|中|低 + 主要不確定性>
NOTES_PATH: <落檔路徑>
```

## T5 審查（驗別人的工；fresh context，不給實作過程）

適用：驗收 T2/T3 的產出、審 root cause、對抗審查文件。model：**sonnet**；高風險判斷 → **opus**。

```
你是 fresh-context 審查者，沒有參與實作，這是刻意的——不要向實作者對齊，向規格對齊。
受審物：{diff / 文件路徑 / 分支}
規格與驗收條件（審查的唯一依據）：{逐條}
審法：
- 逐條驗收：自己重新執行驗證指令（不信任受審物附的輸出）
- 主動找茬：{該類產出的已知失效模式，如「測試改綠但沒測到修復點」「路徑寫錯」「規則互相矛盾」}
- 對每個問題給 file:line + 嚴重度（BLOCKER/MAJOR/MINOR）+ 一句修法
回報格式：
REVIEW_RESULT: <PASSED|FAILED>
BLOCKERS: <數量；每個一行 file:line + 問題>
REPORT_PATH: <完整報告落檔路徑>
```

常見錯誤：把實作者的自述餵給審查者 → 錨定效應，等於沒審。只給規格和受審物。

## 選型速查

| 我要… | 模板 | 預設 model |
|---|---|---|
| 找出所有呼叫點 / 定位程式碼 | T1 | sonnet |
| 照方案改 code / 批次機械修改 | T2 | sonnet / haiku |
| 消重複、搬結構、不改行為 | T3 | sonnet |
| 弄懂某問題並給建議 | T4 | sonnet（裁定→opus） |
| 驗收、對抗審查 | T5 | sonnet（高風險→opus） |
