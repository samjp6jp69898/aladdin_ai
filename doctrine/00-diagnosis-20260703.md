# Harness 快速診斷（2026-07-03，Fable 5 制度化 session）

> 本檔是後續所有制度檔的依據。證據全部來自當日實測與檔案實讀，非印象。
> 引用格式：`檔案:行號`。金額級距：Haiku $1/$5、Sonnet $2/$10、Opus $5/$25（每百萬 input/output token，2026-07 已驗證）。

## 總覽：這個 harness 的錢和注意力漏在哪

營運規模（實測 2026-07-03）：tracker 共 1383 單（done 91.8%），回測 885 單中完全正確 52.9%、命中（完全+部分）86.5%、分析錯誤 13.5%。單一 `/create-mr` 跑 20–40 分鐘、派 6–8 個 sub agent。**任何 per-ticket 的浪費都要乘上千倍。**

## 一、Token 漏洞 Top 3

### 漏洞 1：manager 整檔 cat 166KB tracker（最大單一漏洞）
- **證據**：`bug_analysis_tracker.md` 實測 166,362 bytes（≈4–5 萬 token）。`create-mr.md` Step 0.1 要求 `cat` 整檔；`create-mrs.md` Step 1 讀全檔、Step 4c 每單完成後「Re-read tracker」、Step 4e refill 再讀。
- **影響**：一場 10 單 batch ≈ 12+ 次全檔讀 ≈ 50 萬+ token 純粹浪費，且把 manager context 塞爆、加速壓縮失憶。
- **修法**（已於本次 session 實作）：新增 `scripts/tracker.sh`（grep/awk 行級操作：`next`、`row`、`set`、`counts`），manager 只准用它碰 tracker，禁止 cat 全檔、禁止用 Edit tool 改 166KB 檔。

### 漏洞 2：agent prompt 雙重載入（「Use all text in {agent.md} as the prompt」模式）
- **證據**：`bug-tracer-with-callgraph.md` 58,974 bytes（≈1.5 萬 token）。舊版 `create-mr.md` 每次 dispatch 都要求 sub agent「把該檔全文當 prompt」——但這些 agent **已註冊**在 `.claude/agents/`（21 個全部有 `model:` frontmatter），註冊 agent 的 .md 本來就是它的 system prompt。照舊寫法，同一份 58KB 會出現兩次（system prompt + agent 自己再 Read 一次）。
- **影響**：tracer 每次 dispatch 多燒 ≈1.5 萬 token；全 pipeline 每單多燒 3–5 萬。
- **修法**（已實作）：dispatch 一律 `subagent_type: <agent名>` 直接引用註冊 agent，prompt 只放變數（ticket_id、路徑、回報格式），刪除「Use all text in …」句式。

### 漏洞 3：常駐載入面（每個 session、每個 subagent 都付一次）
- **證據**：專案 CLAUDE.md 15,517 bytes（≈4k token，其中兩段 worktree 踩坑敘事 ≈1.5k 只在 create-mr Step 4 用得到）+ 使用者層 CLAUDE.md（工具呼叫格式長篇敘事）+ superpowers plugin SessionStart hook 每次注入 ≈1.2k token（`~/.claude/plugins/cache/claude-plugins-official/superpowers/6.1.1/hooks/hooks.json`，matcher `startup|clear|compact`）。
- **影響**：每個 session ≈7–8k token 起手；**每個 sub agent 也載一份專案 CLAUDE.md**，一單 6–8 個 agent 就是 3 萬+。
- **修法**（已實作 CLAUDE.md 部分）：CLAUDE.md 只留不變式 + 路由表，敘事抽到 `.claude/doctrine/refs/`（按需讀）。superpowers hook 屬使用者安裝的 plugin，**本 session 不代改**——建議見 `50-letter-to-future-sessions.md`。

## 二、失焦模式 Top 3

### 失焦 1：batch 長跑 → context 壓縮 → 迴圈狀態失憶
- **證據**：`create-mrs.md` 一場 10 單 × 每單 20–40 分鐘；harness 會做 context 摘要。舊版把 completed counter、working list 放在對話記憶裡，壓縮後 manager 忘記進度，靠猜。
- **修法**（已實作）：迴圈改「無狀態設計」——每輪開始都從 tracker + lock 目錄重新推導（`tracker.sh counts` + `bug-lock.sh list`），明文規定「檔案是唯一事實，對話記憶不可信」。

### 失焦 2：規則互相矛盾時，弱模型現場即興
- **證據**：舊版 `create-mr.md` 自身矛盾——Pipeline Failure 段寫「失敗路徑不上傳 Drive 文件」，Step 7a 卻寫「failed 路徑 → drive-uploader-mr 會回傳 DRIVE_LINK: N/A」（暗示要跑 7a）；`create-mrs.md` Step 4a 先 claim 鎖再派 `/create-mr`，而 `/create-mr` Step 0.1 又要 claim 同一把鎖（`bug-lock.sh` 是 mkdir 原子鎖，第二次 claim 必然 `LOCKED` exit 1）且要求狀態必須是 pending/rerun（但 4a 已改成 in_progress）——照字面執行必然自我 SKIP。強模型會腦補繞過，弱模型會卡死或亂做。
- **修法**（已實作）：分工改為「create-mrs 只挑單，claim/標記全部由 create-mr 做」；failed 路徑明文「不跑 7a」。維護協議（`40-maintenance-protocol.md`）規定：任何人改流程檔，必須 grep 同名關鍵字檢查上下游是否矛盾。

### 失焦 3：superpowers 儀式與自主 pipeline 打架
- **證據**：SessionStart hook 要求「任何動作前必須先 invoke skill、創作前必須 brainstorming（互動式）」；而 `/create-mrs` 明文「entire loop is fully automatic、不等使用者」。兩者對弱模型是直接衝突，會導致 batch session 開場先跑一輪無關儀式、甚至停下來問問題。
- **修法**：pipeline 指令檔開頭加一行豁免聲明（本次已在 create-mr/create-mrs 加上「本指令為自主 pipeline，superpowers 流程類 skill 不適用」）；根本解（停用或改 hook）屬使用者決策，見信件檔。

## 三、易錯點 Top 3

### 易錯 1：大段 inline bash 模板要弱模型手工展開
- **證據**：舊版 `create-mr.md` Step 4 有 60 行 bash，`{ticket_id}`/`{affected_repos}` 佔位符要模型自己代入；且**未收錄** CLAUDE.md 記錄的兩條踩坑（abu 多子專案 node_modules 分散 → 頂層 symlink 失效 → `ENV_MISSING:node_modules:abu`；rajah 入列時 agrabah/.env.local 不會被 checkout → migrate 硬中斷）。
- **修法**（已實作）：抽成 `scripts/setup-worktree.sh <ticket_id> <repo...>`，把兩條踩坑寫成確定性 shell 邏輯（多子專案偵測、.env.local symlink、migrate 卡點判別），模型只呼叫、不展開。

### 易錯 2：路徑/工具名漂移（文件說的 ≠ 環境真的）
- **證據**：`create-mrs.md` 叫模型用「SlashCommand tool」——本環境該工具名為 `Skill`；舊 create-mr.md 說 tech-users.csv 是 4 欄，實際含 `tg_chat_id` 5 欄；文件宣稱腳本在根 `scripts/`、盤點 agent 回報在 `obsidian/scripts/`——實測（inode 比對）兩者是 **symlink 同一份**（`.claude/commands`、`.claude/agents`、`.claude/skills`、`scripts` 全部 symlink → obsidian 對應目錄），唯一真雙實體是 CLAUDE.md ×2。連 AI 盤點都會被 symlink 騙，何況弱模型。
- **附帶環境陷阱（實測）**：BSD find 與 harness 的 bfs 包裝對「本身是 symlink 的目錄」當作路徑參數時**靜默回空**（exit 0、無 stderr）。腳本遍歷這類目錄必須用實體路徑或先 `cd` 進去再用相對路徑。
- **修法**（已實作）：新增 `scripts/sync-mirrors.sh`（同步唯一的 CLAUDE.md 配對 + 健檢四個 symlink 沒被換成真目錄）；維護協議規定「腳本與文件不一致時，以腳本為準並當場修文件」「引用路徑前先 `ls -ld` 確認身分」。

### 易錯 3：機密與 API 呼叫散裝硬編
- **證據**：Notion token 明文出現在舊 `create-mr.md` ×8 處 + `scripts/notion.sh`。四段幾乎相同的 curl JSON（Step 7c）要弱模型手工代入變數與跳脫引號——JSON 跳脫是弱模型高頻錯誤區。
- **修法**（已實作）：create-mr.md 內 8 處 token 明文清零，Notion 寫回全部改走 `notion.sh comment-text / update-prop` 包裝。**注意：token 並未全域單源化**——明文仍存在於 `agents/{bug-report-analyst,drive-uploader-mr,drive-uploader,mr-pusher}.md`、`scripts/{notion-backtest-query,notion-bug-query,notion-bug-query-v2}.ts`、`sync-bug-tracker.py` 共 8 檔（含 git 歷史與備份）。輪替 token 時上述清單必須全改，否則 pipeline 半癱（見信件檔待決事項）。

## 四、與品質相關但本次不硬修的事實（供 D/G 引用）

1. **頭號卡點是規格模糊，不是程式能力**：179 次 grounding 有 18 次（~10%）NEEDS_QA_CLARIFICATION，全屬「spec 自相矛盾／by-design vs bug 需業務裁定」（例：FAQ-430、FAQ-3075）。這類問題**換更強模型也不該自裁**，制度上正確做法就是現行的停下來問 QA——判準見 `20-judgment-rubrics.md`。
2. **分析錯誤率 13.5%**（回測 820 可比對單中 111 錯）：這是 tracer 判斷力上限的量化基線。改善路徑是把回測「分析與失效模式」27 條規則迴流進 tracer 的檢查清單，而不是無限加長 tracer prompt（已 58KB）。
3. **CQA 唯讀 DB（18.179.234.223:3306）反覆連不上**：grounding 已有降級路徑（改用 source/ORM 佐證）。這是環境問題，修法在網路/白名單層，AI 端只能顯式標注降級。
